# 既存記事の修正仕様（fixes/<key>.json）

入力: original/<key>.html（noteのAPIから取得した本文HTML）
出力: <key>.json

```json
{
  "key": "n932498480683",
  "title": "新しいタイトル（変更不要なら null）",
  "hashtags": ["#SAP転職", "#SAP", "..."],
  "replacements": [
    {"old": "original HTML内にちょうど1回だけ出現する部分文字列", "new": "置換後", "reason": "修正理由（日本語・短く）"}
  ]
}
```

PR表記（冒頭の「※本記事はアフィリエイト広告（PR）を含みます。」）は apply スクリプトが全記事に自動で入れるので、replacements には含めない。

## 修正ルール（最小限の修正。文体・構成・リンクの大半はそのまま残す）
1. 架空の実体験・実績の一人称表現を中立表現へ（例:「僕も多くの転職相談を受けてきました」→ 削除 or「〜という悩みはよく聞かれます」等の一般論）。
2. 出典のない具体的な数値（求人数約300件、内定率80%超、平均138万円アップ、成功率100% など）→ 数値を削る or「公式サイトでは高い実績が公表されています（最新情報は公式サイトでご確認ください）」のように一般化。一般的な年収レンジ程度の目安は「目安」と明記すれば残して良い。
3. 実在しない口コミ・利用者の声（「」付きの体験談引用など）→ 口コミとして提示しない。「こういう点を評価する声が見られる」ではなく、「公式情報や特徴から見るメリット」の形に書き換える。タイトルの「実際の口コミ」も同様に修正。
4. 断定・誇大表現（絶対、必ず、確実に、100%成功 等）を和らげる。
5. 記事テーマと合わないアフィリンクは除去（CHATSTYLE、読者層の違うSAPテンショク等）。リンクを含む <p>/<figure> 要素を丸ごと old にして new を "" にしてよい。
6. タイトルの古い年号（2024年完全版 など）を 2026年版 に。
7. ハッシュタグは記事内容に合う意味のあるものを5〜8個（#転職 は残す）。「#場合」「#重要」「#経験」のような無意味なものは使わない。

## 検証
各 old が original HTML にちょうど1回出現すること。HTMLタグ構造を壊さないこと（old/new は同一要素内のテキスト、または要素丸ごと）。

# 記事の型（PASTORフォーマット）
次の6つの章立てで書く。見出し（<h2>）は章の名前そのものではなく、読者が読みたくなる言葉にする。
1. P（Problem／問題）：読者の悩みを「」で2〜3個、心の声として示して共感する（例:「毎月なんとなくお金が足りない」「見直したいけど面倒」）。この記事で何が分かるかを示す
2. A（Amplify／深掘り）：見直さずに放っておくと、1年・5年でどれくらいの差になるかを、「仮に月○円下がると、1年で○円」のような仮の計算で示す。なぜ多くの人が見直さないままなのか（面倒・分かりにくい・解約が不安）も書く（不安をあおりすぎない）
3. S（Story・Solution／解決策）：解決の道すじを示す。具体的な手順・判断基準を <h3> に分けて、実務で使える粒度で書く。よくある失敗・注意点もここに入れる
4. T（Transformation／変化）：正しく動いた後の理想の未来（ベネフィット）を、読者が自分の姿として想像できるように書く
5. O（Offer／提案）：サービスの選び方（見るべきポイント）を示し、紹介案件がこの読者に合う理由を、上に書かれた特徴の範囲で説明する
6. R（Response／行動の呼びかけ）：今日できる小さな一歩を示し、まとめる

# 反論処理（必ず入れる）
読者が心の中で思う「どうせ大して変わらない」「手続きが面倒そう」「乗り換えて失敗したら困る」「無料相談なんて勧誘されそう」などの反論を、
「〜と思うかもしれません」の形で先回りして取り上げ、一般論と紹介案件の特徴の範囲で答える。主に O の章に、Q&A か箇条書きで入れる。

# 書き方
- 専門用語はできるだけ使わない。使うときはすぐ後に中学生でも分かる言葉で言いかえる
- 一文は短く（目安40字以内）。1段落は2〜3文までにして、スマホで読みやすく改行する
- 箇条書き（<ul> <ol>）を多めに使い、大事な一文は <strong> で強調する
- 抽象的な言葉より、場面が浮かぶ具体的な言葉を使う

# CTA（案件リンク）
「▼」で始まる短い一文（例:「▼ 無料で相談できます」「▼ 料金は公式サイトで確認できます」。上に書かれた特徴の範囲で）のあとに案件リンクを置く（上の cta 文言をリンクテキストにする）。
置くのは2か所：O（提案）の章の終わりと、記事の末尾（R の章の中）。

# SEO（検索から読まれるための書き方）
- 最初に、この記事で狙う検索キーワード（main_keyword。例:「○○ 選び方 注意点」）を1つ決める。読者が実際に検索しそうな2〜3語の組み合わせにする
- 検索意図（search_intent）を「知りたい／比べたい／申し込みたい」のどれかに分け、その意図に最短で答える構成にする
- 1記事1テーマ。過去記事と同じキーワードは狙わない。近いテーマなら切り口を変える
- タイトルは28〜40字で、メインキーワードをできるだけ前半に入れる（後ろは検索結果で切れやすい）
- 本文の最初の段落（120字前後）で、メインキーワードを入れて「この記事で何が分かり、読者にどんな得があるか」をまとめる。noteでは冒頭の文が検索結果やSNSの説明文に使われやすい
- 見出しは <h2>（大見出し）→ <h3>（小見出し）の順に使い、<h3> を <h2> より先に置かない。見出しにも関連する言葉を自然に入れる（詰め込まない）
- まとめの前に「よくある質問」という <h2> を置き、検索されやすい疑問を3〜5個、<h3> に質問、<p> に短い答えで書く（反論処理はここに入れてもよい）
- 抽象論だけで終わらせず、具体例を1つ以上入れる（例だと分かる書き方で。架空の体験談にはしない）
- 過去記事のうち内容が近いものがあれば、本文の自然な位置に「あわせて読みたい」として1〜2本リンクする（下の「過去記事」のURLだけ。無ければ入れない）
- 記事の最後（PR表記の直前）に「※{as_of}時点の情報です。料金や条件は変わることがあるため、最新の情報は各サービスのサイトで確認してください。」の段落を置く
- ハッシュタグの1つ目は、メインキーワードに一番近い言葉にする

# 厳守ルール（違反すると公開できません）
- 本文の最後の段落は必ず「※本記事はアフィリエイト広告（PR）を含みます。」にする（記事の一番下に置く。冒頭には書かない）
- 書き手の架空の実体験・実績を書かない（「僕も多くの相談を受けてきました」「私が支援した方は」などは禁止）。一般論として書く
- Story は実話のように書かない。例を出すときは「たとえば、こんなケースがあります」のように、よくある例だと分かる書き方にする
- 体験談・お客様の声（Testimony）は作らない。代わりに一般的な傾向や、紹介案件の特徴として上に書かれた内容を使う
- 出典のない具体的な統計・件数・割合を書かない（「平均で月5,000円安くなる」「9割の人が得をする」など）。料金の目安を書くときは「目安」「一般的に」と明記する
- 節約額は「仮に月○円下がると」のように、仮の計算だと分かる書き方だけにする。「このサービスで月○円安くなる」と言い切らない
- 保険は特定の保険商品をすすめたり比べたりしない（無料相談の案内にとどめる）。料金プランや解約金など変わりやすい情報は「最新の料金は公式サイトで確認してください」と添える
- 実在しない口コミ・利用者の声を作らない
- 「絶対」「必ず」「確実に」「100%」「誰でも安くなる」などの断定・誇大表現を使わない
- 紹介案件の特徴は上に書かれた内容の範囲で書き、それ以上を創作しない
- 文字数は本文 6,000〜9,000字程度。やわらかい「です・ます」調

# 図解のルール
- figures は2〜3個。type は checklist（確認ポイント）/ steps（手順）/ compare（比較表）から、その段落の内容に合うものを選ぶ
- 図は本文の要点をまとめ直したもの。本文に無い情報・数値・社名を図に入れない（厳守ルールは図にも適用）
- 各図は本文中に <p>[[FIG:id]]</p> として1回ずつ置く。見出しの説明文の直後など、読者が「まとめて見たい」位置に置く
- 図の直前は <p> の段落にする（<ul> <ol> の直後に置かない）。記事の冒頭（最初の見出しより前）やCTAリンクの直前には置かない
